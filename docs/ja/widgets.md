---
title: ウィジェット
description: オプションのシステムテレメトリウィジェットを設定します。
---
`argvus widget-telemetry`は、システム情報用のオプションの補助Waybarサーフェスを提供します。現在のブロックは**System（システム）**、**CPU/GPU**、**Memory（メモリ）**、**Storage（ストレージ）**、**Processes（プロセス）**、**Network（ネットワーク）**、**Shortcuts（ショートカット）**です。Shortcutsブロックは、状態ファイルで`keys`というキーで保存されます。

**Control Center → Appearance → Widget Telemetry**を使って、サーフェスを有効にし、個別のブロックをオンまたはオフに切り替えます。ブロックを無効にすると、そのテレメトリモジュールはWaybarプロファイルから非表示になります。パッケージのアンインストールやセッションの他の部分の停止は行われません。マスタートグルは、テレメトリサーフェス全体を制御します。

ブロック選択は `config.json` の `control_panel.widget_telemetry_blocks` で標準的であり、マスタースイッチは `control_panel.widget_telemetry_enabled` です。`argvus-config` は、その限定された  `data/waybar/argvus-widget-telemetry.jsonc` `ARGVUS_TELEMETRY_<BLOCK>_BEGIN`/`_END` ブロック内の行のコメント解除またはコメント化を行うことで、Waybar プロファイル data/waybar/argvus-widget-telemetry.jsonc に選択を反映し、ファイルの他の部分には手を付けません。旧式の `~/.local/state/argvus/widget-telemetry-blocks` ファイルは、古いインストールでのマイグレーションフォールバックとしてまだ読み込まれますが、書き込まれることはありません。見た目の変更時にはパッケージ化されたデフォルトでプロファイル全体が置き換えられるため、ブロックマーカーが選択の保持方法となります。ブロック外のテキストはテーマ切り替え時に保持されません。

コントローラーは以下をサポートします:

```sh
argvus widget-telemetry-toggle status
argvus widget-telemetry-toggle on
argvus widget-telemetry-toggle off
argvus widget-telemetry-toggle blocks status
argvus widget-telemetry-toggle blocks set memory disabled
argvus widget-telemetry-toggle blocks apply
```
コントローラーは、 `blocks set <block> <enabled|disabled>` `system`、`cpu_gpu`、`memory`、`storage`、`processes`、`network`、および`keys`に対して、blocks set <block> <enabled|disabled>も受け入れます。設定は持続的です。ブロックに明示的な設定がない場合は、有効なデフォルトに従います。`blocks set`は、標準配列を単一のアトミックパッチで書き換え、その後Waybarプロファイルを再投影し、サービスのライフサイクルを調整します。`apply-state`はコントロールセンターのパスです。呼び出し元が選択をすでに保持していることを前提としており、それを投影するだけなので、保存されていない状態で呼び出してはいけません。

サービスは`argvus-widget-telemetry.service`で、`argvus-session`によって管理されています。現在のページにはブロックごとのリセットボタンはありません。ブロックを再度有効にするか、生成されたWaybar出力を編集する代わりに、プロバイダーがサポートする状態管理を使用してください。

## 透明性とぼかし

マスター スイッチ、テレメトリ セッション、透明度およびぼかしを構成するには、**コントロールセンター → 外観 → ウィジェット テレメトリ** を使用します。両方の効果には独立した有効化スイッチおよび `0–100%` の値があります。`+` および `-` を5％ステップで使用し、**[適用]** を選択します。値は確認後にのみ適用され、アクティブテーマに保存されます。  
有効化行と値の行の間を移動するには `↑/↓` を使用します。**アクション** を行うには `Tab` を押し、次に **[適用]** を有効化します。

GPU温度モジュールは、DRM/sysfsがサポートされているNVIDIA、AMD、またはIntel GPUを公開し、`btop`がインストールされている場合に表示されます。その値は、検出されたGPUのうち1つに割り当て可能な有効な最大温度です。センサーが公開されていない場合は`N/A`を表示します。クリックすると、`argvus tui-terminal`を使用してKittyでGPU専用のbtopパネルが開き、`taskbar-monitor`プロファイルが使用されます。閉じるには`q`または`Esc`を押してください。ローカライズされた下部タブには`Press q to close`と表示されます。btop 1.4.7は最大6つのGPUボックスをサポートします。NVIDIAのメトリクスにはbtop GPUサポートとNVMLが必要です。AMDにはbtop GPUサポートとROCm SMIが必要です。Intelには読み取り可能なsysfsインターフェースが必要です。NVIDIA nouveau、AMD、およびIntelの温度は、リンクされたhwmonセンサーが公開されている場合にのみ表示されます。ARGVUSは権限を変更したり、特権付きヘルパーを追加したりしません。タスクバーのパッケージはbtopに依存します。メーカー提供のプロバイダーは任意です。


グループ/右端-2 のオプションの AI エージェントアイコンは argvus-ai メニューを開きます。5 秒ごとにチェックされ、ヘルパーがいない場合や利用可能なエージェントがない場合（argvus-ai status --check）には非表示になります。mise が存在する場合、Claude がインストール可能として提示されます。それを選択すると ARGVUS ターミナルが開き、存在しない場合は現在のユーザープロファイルにインストールされ、バイナリディレクトリをプロセス PATH に含めて起動されます。パッケージインストールフックは使用されません。システム構成を更新するにはバーをリロードしてください。ユーザーコピーは上書きされません。

AI ランチャーは Symbols Nerd Font Mono の nf-md-robot (U+F06A9) を使用します。表示プロジェクターは、マイクとオーディオコントロールとともに、グループ/右端-2 にそれを保持します。

## ウィンドウモードセレクター

`group/right-2` のウィンドウアイコンは、ユーティリティ拡張後に GTK ポップアップを開き、**タイルウィンドウ（デフォルト）** と **フローティングウィンドウ** が表示されます。現在の設定がマークされています。項目を選択するとすぐに適用されます。Escape キーまたはポップアップ外のクリックで閉じることができます。アイコンは有効なモードを反映し、アプリケーションが完了していない場合は保留/エラー表示になります。ポップアップはタスクバーの位置と現在のテーマに従います。

この設定は **コントロールセンター → デスクトップ＆入力 → Hyprland → ウィンドウ → モード** と共有されています。フローティングはすべてのアプリケーションウィンドウに、モニターおよびワークスペース全体で影響します。タイルに戻しても、元々フローティングだったウィンドウは保持されます。選択内容はログイン間で保持されます。

ヘルパーは `argvus window-mode-menu` です；`argvus window-mode-menu --status` は Waybar JSON を出力します。これはマスター `argvus` パッケージで提供されます。既存のカスタマイズされたタスクバーのコピーは保持されます：パッケージ化されたテンプレートから `custom/window-mode` モジュール定義とグループエントリを追加して参加するか、またはコントロールセンターを使用してください。外観プロジェクターは、他のユーティリティアイコンが無効でも、定義が存在する場合はモジュールを保持します。

## ウィンドウボタンとアプリケーションバー

フローティングモードは、通常のアプリケーションウィンドウに ARGVUS タイトルバー（**最小化**、**最大化 / 元に戻す**、**閉じる**）を追加します。タイトルバーをダブルクリックすると最大化が切り替わります。追加の装飾はタイル表示および全画面表示中は非表示です。独自にコントロールを描画するアプリケーションは両方のバーを表示することがあります；統一された ARGVUS コントロールは意図的です。

セカンドWaybarは、すべてのモニターに表示され、メインタスクバーとは反対の端に配置されます。そのモニターの現在のワークスペースのウィンドウのみを一覧表示し、最小化されたウィンドウも含まれます。非表示のグループタブは追加のエントリを作成しません。最小化されたエントリは元のモニター／ワークスペースの関連付けを保持します。非アクティブウィンドウをクリックするとアクティブ化され、アクティブウィンドウをクリックすると最小化され、最小化されたウィンドウをクリックすると復元されます。そのコンテキストメニューには、復元、最小化、最大化／復元、閉じるが用意されています。未確認のアプリケーションアイコンはウィンドウのシンボルが代わりに表示されます。エントリをアクティブ化または復元してもポインタの位置は保持されます。セカンダリバーは、実際のプライマリCSS（色、フォント、ボーダー、角の丸み）を使用し、高さと反対側の端のミラーされたマージンを持ちます。

`SUPER + Alt + Up`はメインバーを上に、ウィンドウバーを下に配置します。`SUPER + Alt + Down`はその逆を行います。同じ方向を繰り返すと、位置は変更されません。タイルにはメインバーのみがあります。タイルに戻ると、ウィンドウバーを削除する前にすべての最小化されたウィンドウを復元し、その後、元のタイル/フローティングのポリシーを保持します。

最小化は予約された `special:argvus-minimized` ワークスペースを使用します。そのワークスペースを手動で使用しないでください。`argvus windows service` プロセスは、識別情報、元のワークスペース/モニター、ジオメトリ、全画面/最大化状態、およびピン状態を、コンポジタインスタンス固有のランタイムレジストリの `$XDG_RUNTIME_DIR/argvus` 下に記録します。記録はサービスの再起動や設定の再読み込み後も保持されますが、コンポジタセッションをまたぐことはありません。ウィンドウを閉じると、その記録は削除されます。モニターが消えた場合、復元は利用可能な出力を使用します。欠落または復旧に失敗したバーは新しい最小化を防ぎます。復元に失敗しても記録と復旧バーは保持されます。

セッションは `argvus-windows.service` および `argvus-window-bar.service` を所有します。後者は Waybar の子を Tile 内で休止状態に保ちます。hyprbars プラグインは `argvus-hyprland` によってバンドルされ、x86_64 上の Hyprland 0.57.0 ABI 用にビルドされています。ユーザーのホームディレクトリでコンパイルされたものではありません。コンポジタ ABI のアップデート時にはプラグインを再ビルドしてください。コマンド: `argvus windows list --json`、`watch --json`、`position top|bottom`、`restore-all`、および `minimize|restore|activate|maximize|close ADDRESS`。ウィンドウアドレスはリストから取得されます。`position top --persist` はメインバーを再起動せずに設定を保存/適用します。構成および実行時のエラーの詳細はジャーナルに書き込まれます。表示可能なアクションの失敗も翻訳された通知として表示されます。

**Spaced + Floating** では、ウィンドウは外側のギャップと両方のバーによって確保された領域を尊重します。ボーダーとタイトルを含む境界は、同じウィンドウボーダー内にタイトルが配置されます。ARGVUS コントロールを使った最大化は、この領域をマージン付きで埋めます。復元するとサービス再起動後も以前のジオメトリを回復します。フルスクリーンは依然として出力全体を使用します。フローティングウィンドウは重なり合う可能性があります。タイル内の内部ギャップはそれらを分離しません。
